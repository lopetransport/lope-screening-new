# Lope screening front end

React 19 + TypeScript + Vite + Tailwind CSS 4. A local reconstruction of the five-step hauler registration portal. See [FLOW-BLUEPRINT.md](./FLOW-BLUEPRINT.md) for evidence, option sets and recovery gaps.

## Run

Use Node 22.x (22.12 or newer). See [DEPLOY-VERCEL.md](./DEPLOY-VERCEL.md) for the ready-to-use Vercel configuration and deployment steps.

```sh
npm ci
npm run dev
```

Open the printed localhost URL. Build with `npm run build`, run validation tests with `npm test`, and serve the production build with `npm run preview`. Deploy `dist/` as a static site (including Vercel). No secret belongs in any `VITE_` variable: these values are public browser configuration.

## Connect a backend

Copy `.env.example` to `.env.local`. Configure `VITE_APPLICATION_ENDPOINT`, `VITE_TERMS_TEXT` and `VITE_PRIVACY_TEXT` with the intended API and approved policy text; restart/rebuild after changes. Policy text should accurately describe the backend you implement. With an endpoint configured, missing policy text blocks submission. With no endpoint, the final button validates and shows **Application ready for integration**, explicitly stating that nothing was sent.

The browser sends `POST` multipart/form-data:

- `application`: JSON matching `application.schema.json`, generated by `payload()` in `src/model.ts`.
- One binary field for every document, named `document_<document ID>`. The corresponding metadata includes `multipartField`.

Do not manually set the multipart Content-Type header; the browser generates its boundary. Success must return HTTP 2xx and JSON `{ "applicationId": "your-reference" }`. HTTP errors/network failures remain on the form and preserve values/files for retry. No account details are printed to the console. No JSON download exposes sensitive fields by default.

Backend work still required: validate every field and enum again, authenticate/protect the endpoint as appropriate, limit body size/file count, inspect file contents rather than trusting MIME, scan uploads, store data/files securely, record authoritative consent timestamps and approved policy versions, enforce idempotency and return a receipt. Cross-origin APIs need appropriate CORS. The UI alone does not verify identity, bank ownership or document authenticity.

Draft saving is opt-in, session-scoped and excludes files. It stores identity and banking values in sessionStorage only when selected. It clears on tab closure according to browser session behavior (browser session restoration may retain it). Successful real submission removes the saved draft. Future drafts are not written after success unless the form is reopened/edited. If persistent cross-device drafts are required, implement them through the backend.
